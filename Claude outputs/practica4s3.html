S3 · modelo mental

Un disco infinito, accesible por HTTP

S3 (Simple Storage Service) es el almacenamiento de objetos de AWS: no administrás ni servidor ni disco, subís objetos y pagás por lo que guardás.

El contenedor

Bucket

La carpeta raíz donde se guarda todo. Su nombre tiene que ser único a nivel mundial en AWS.

clase-isw-files-20260330

El contenido

Objeto

Cualquier archivo que subas. Tiene una clave (su nombre), el contenido y metadata.

datos20260330.csv

El lugar

Región

El bucket vive en una región. Usamos us-east-1: es la más barata. sa-east-1 (São Paulo) tiene menos latencia desde acá.

us-east-1

S3 · para qué se usa

Cuatro usos típicos

Aplicaciones

Imágenes y videos

El contenido pesado no vive en la base de datos ni en el servidor de la app.

Operación

Backups y logs

Barato, durable y con reglas de ciclo de vida para archivar lo viejo.

Web

Lo que vamos a hacer

Data lake

S3 · el detalle que importa

Cada objeto tiene su propia URL

https:// clase-isw-files-20260330bucket .s3. us-east-1región .amazonaws.com/ datos20260330.csvclave del objeto
Consecuencia 1

El Access Denied es la respuesta correcta

Si pegás esa URL en el navegador, S3 responde Access Denied: el bucket bloquea el acceso público. La URL existe, el permiso no.

Consecuencia 2

Por eso el nombre es único en el mundo

El bucket es un subdominio de amazonaws.com. Dos buckets con el mismo nombre serían la misma URL: por eso AWS no deja repetirlos.

S3 · el malentendido clásico

No hay carpetas, hay prefijos

Lo que vesaws s3 ls
$ aws s3 ls s3://$FILES

                   PRE  reportes/
2026-03-30    1247  datos20260330.csv
2026-03-30     612  notas.txt

Parece que hay una carpeta reportes y dos archivos al lado.

Lo que hayaws s3 ls --recursive
$ aws s3 ls s3://$FILES --recursive

2026-03-30    1247  datos20260330.csv
2026-03-30     612  notas.txt
2026-03-30     498  reportes/reporte-marzo.txt
2026-03-30     441  reportes/reporte-abril.txt

Cuatro objetos y ninguna carpeta. reportes/ es parte del nombre de dos de ellos.

Consecuencia práctica: en S3 no existe mkdir, y borrar “la carpeta” es borrar todos los objetos cuyo nombre empiece con reportes/. La consola te dibuja el árbol; abajo solo hay una lista plana de claves.

AWS CLI · aws s3

Con cinco verbos hacés todo el trabajo

# el nombre del bucket, una vez
FILES=clase-isw-files-20260330

# crear un bucket (nombre único a nivel mundial)
aws s3 mb s3://clase-isw-athena-20260330

# listar: los buckets, el contenido, todo el árbol
aws s3 ls
aws s3 ls s3://$FILES --recursive

# subir: origen local → destino S3
aws s3 cp ejemplos/archivos/notas.txt s3://$FILES/

# bajar: origen S3 → destino local
aws s3 cp s3://$FILES/notas.txt ./bajado.txt

# borrar un objeto
aws s3 rm s3://$FILES/notas.txt

# sincronizar una carpeta local con el bucket
aws s3 sync ejemplos/archivos s3://$FILES
1

mb crea el bucket. ls sin argumentos lista buckets; con s3:// lista objetos, y --recursive entra en todos los prefijos.

2

cp es siempre origen y después destino. El que empieza con s3:// define si subís o bajás.

3

rm borra sin preguntar y sin papelera. Con versioning apagado, no hay vuelta atrás.

4

sync es lo más potente: sube solo lo que cambió, igual que rsync. Se usa para backups y deploys.

Web estática · lo que hace falta

Un bucket público son cuatro cosas

Subir el HTML no alcanza. El bucket que ya sabemos crear es privado: para que sirva una web hay que agregarle tres cosas más.

Pieza 1

El bucket y los objetos

Igual que el de la parte 1. Se suben con sync, y index.html tiene que quedar en la raíz.

Pieza 2

Website configuration

Properties → Static website hosting → Enable. Dos campos: index.html y error.html.

Pieza 3

Destrabar el bloqueo

Permissions → Block public access → Edit. Es el candado de arriba: mientras esté puesto, ninguna policy tiene efecto.

Pieza 4

La bucket policy

El permiso real. Las tres piezas anteriores no dan acceso a nadie: esta sí.

Permissions · bucket policy

La policy que lo hace público

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PermitirLecturaPublica",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::clase-isw-web-20260330/*"
    }
  ]
}
1

Principal: "*" es literalmente “cualquiera”, sin credenciales. Es lo que hace pública la web, y lo que no hay que escribir por accidente.

2

GetObject y nada más: se puede leer, no escribir ni listar. Sin ListBucket, nadie puede pedir el inventario del bucket.

3

El /* del final son los objetos. El ARN sin barra es el bucket: son dos recursos distintos, y esta policy solo habla de los objetos.

4

Cuando la consola muestre Publicly accessible en rojo, no es un error: es exactamente lo que pedimos.

Web estática · el detalle que confunde

El mismo bucket, dos endpoints

http://sin TLS clase-isw-web-20260330bucket .s3-website-endpoint web us-east-1región .amazonaws.com/
Resuelve el índice

La raíz devuelve algo

Pedir / devuelve index.html. El endpoint normal, el de .s3., no resuelve índices.

Resuelve el error

404 con tu propio HTML

Una clave que no existe devuelve error.html. Sin website hosting, S3 responde NoSuchKey en XML.

No hace TLS

Solo http

El endpoint web no habla https. Para eso hace falta CloudFront adelante — otra clase.

Athena · qué es

SQL sobre archivos, sin base de datos

Consultás directamente los archivos que están en S3: sin cargar datos, sin instancia, sin infraestructura que administrar.

Origen
datos.csv en S3

El archivo se queda donde está. Athena no lo copia ni lo mueve.

→
Definición
Athena define la estructura

Una tabla externa dice qué columnas tiene ese archivo. Es metadata, no datos.

→
Consulta
SQL de siempre

SELECT, WHERE, GROUP BY. Se paga por los datos escaneados.

Paso 1

Entrar al Query Editor

Barra de búsqueda → Athena. La URL tiene que terminar en #/query-editor; si no, estás en otra pantalla del servicio.

Paso 2

Decirle dónde guardar los resultados

Athena escribe cada resultado en S3 antes de mostrarlo. Pestaña Settings → Manage → Location of query result:

s3://clase-isw-athena-20260330/resultados/

Sin esto la primera consulta falla con No output location provided — y la barra del final no es opcional.

Athena · query editor · database default

La tabla que apunta al CSV

CREATE EXTERNAL TABLE IF NOT EXISTS personas (
    nombre  STRING,
    edad    INT,
    ciudad  STRING
)
ROW FORMAT DELIMITED
FIELDS TERMINATED BY ','
LINES TERMINATED BY '\n'
LOCATION 's3://clase-isw-athena-20260330/datos/personas/'
TBLPROPERTIES ('skip.header.line.count'='1');
1

Antes de ejecutar, verificá que el selector Database diga default.

2

EXTERNAL: la tabla es solo una definición. Si la borrás, el CSV en S3 sigue intacto.

3

LOCATION es un prefijo, no un archivo: Athena lee todo lo que haya ahí. Por eso ventas tiene su propio prefijo, y los resultados van a resultados/.

4

skip.header.line.count evita que la fila de encabezado entre como un dato más.

Athena · consultar

Tres columnas, una tabla, cero infraestructura

Le dijimos a Athena: “el CSV que está en ese prefijo tiene estas tres columnas; tratalo como una tabla llamada personas”.

  • No hay ninguna base de datos corriendo.Nada que prender, apagar ni dimensionar.
  • Los datos no se cargaron a ningún lado.Siguen siendo el mismo CSV en el mismo bucket.
  • Se paga por datos escaneados.Con un archivo de 1 KB, el costo es cero. Con un data lake real, conviene particionar y usar formatos comprimidos.
SELECT * FROM personas;

-- y SQL de verdad, sobre un CSV
SELECT ciudad, COUNT(*), ROUND(AVG(edad))
FROM personas
GROUP BY ciudad;

Athena deja el resultado como CSV en resultados/. Cada consulta escribe un archivo nuevo, así que ese prefijo crece y también se factura.

Terraform · infraestructura como código

Lo mismo, pero en un archivo

Todo lo que clickeamos hoy se puede describir en texto. Terraform lee ese texto, lo compara con lo que hay en AWS y aplica solo la diferencia.

ConsolaTerraform
rehacerloVolver a clickear treinta pantallasterraform apply
revisar un cambioConfiar en quien lo hizoUn diff en un pull request
documentarloUn doc que queda viejoEl archivo es la documentación
treinta alumnosTreinta veces lo mismo, a manoEl mismo repo, treinta apply

No es magia: Terraform usa la misma API que la consola. La diferencia es que queda escrito qué pediste.

terraform/main.tf · el bucket de la web

Cada pantalla que clickeamos es un recurso

resource "aws_s3_bucket" "web" {
  bucket = "clase-isw-web-20260330"
}

resource "aws_s3_bucket_website_configuration" "web" {
  bucket = aws_s3_bucket.web.id
  index_document { suffix = "index.html" }
  error_document { key    = "error.html" }
}

resource "aws_s3_bucket_public_access_block" "web" {
  bucket                  = aws_s3_bucket.web.id
  block_public_policy     = false
  restrict_public_buckets = false
}

resource "aws_s3_bucket_policy" "web" {
  bucket = aws_s3_bucket.web.id
  policy = jsonencode({ /* la de la slide anterior */ })
}
1

Son las cuatro piezas de la parte 3, una por recurso. El bucket no “contiene” su configuración: cada aspecto es un objeto aparte.

2

"web" es el nombre interno de Terraform; bucket = es el nombre real en AWS. El primero se puede renombrar sin tocar nada en la nube.

3

aws_s3_bucket.web.id es una referencia. De ahí Terraform arma el grafo de dependencias y deduce el orden: el archivo no se lee de arriba abajo.

4

Los otros dos buckets son más cortos: solo el bucket y un public_access_block con los cuatro flags en true.

Para llevarse

Ocho ideas

S3 guarda objetos, no archivos en carpetas. La clave es un nombre plano y las carpetas son prefijos que dibuja la consola.

Nada es público por defecto. El Access Denied del navegador es la configuración funcionando.

Un bucket público son cuatro piezas. Bucket, website configuration, destrabar el bloqueo y la policy.

Con mb, ls, cp, rm y sync hacés todo. Y sync se puede repetir sin miedo: sube solo lo que cambió.

Athena no mueve los datos: define una estructura sobre los archivos y cobra por lo escaneado.

Athena también escribe en S3: cada consulta deja un CSV en resultados/, y ese prefijo también se factura.

Todo esto es un archivo de texto. Lo que se clickea una vez, en Terraform se aplica y se reproduce siempre igual.

Lo que prendés, apagalo. terraform destroy al cerrar cada práctica — vaciando los buckets antes.
